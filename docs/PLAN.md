# 기획안

## 초안에서 개선한 내용

- RAG로 규칙 기반 판정 보완, RAGAS로 검색 품질 평가
  - 규칙만으로는 판정이 불확실한 회색 지대가 존재함. 질문 표현을 판정하거나, 응답을 판정하기 애매한 경우를 이번 사례에서 확인할 수 있음. 이 경우, 과거 사례집을 개별 저장소로 저장하면 LLM이 판단할 때 few-shot 검색으로 프롬프트를 작성할 수 있음. 그래서 RAG 파이프라인의 필요성이 강조됨.
  - 결과
    1. (1차) 일정 여부 판단
       1. ✅ RAGAS (질문 표현)
       2. classification metrics
    2. (3차) 응답 긍정/부정 판단
       1. ✅ RAGAS (애매한 응답)
       2. classification metrics
    3. (2차) 날짜 판단 - exact match
    4. (4차) RDB 저장 - success rate
- 실행 케이스에서 "연속적인 대화인지 아닌지(대화의 연속성)" 기준 제거
  - reducer는 새로운 채팅이 추가될 때 리스트에 단순 누적됨. (다만, 같은 ID의 메시지는 overwrite함. 이는 스트리밍을 위한 메커니즘으로, 현재 상황에서는 무관함.) 연속적인 대화인지 판단할 필요가 있는데, 이를 reducer를 기준으로 미확정 질문이 있는지 판단하거나, 별도 변수(State, 일반 변수 등)를 기준으로 판단하는 방법이 있음.
  - 매번 reducer로 파악하는 것은 대화가 길어질수록 처리 비용이 증가하므로, 별도 변수로 관리하는 방법이 적절할 것으로 판단함.
  - 다만, 별도 변수로 관리되더라도 응답 유무에 따라 잔존할 수 있으므로, 질문의 유효 기간(TTL) 개념을 적절히 산정할 필요가 남아 있음. 해당 내용은 추후 재논의 사항으로 남김.

## 1. 처리 흐름

표 1. 실행 순서별 처리 내용 및 평가 지표
| 순서 | 단계 | 내용 | 평가 지표 |
|---|---|---|---|
| 1 | 일정 여부 판단 | 질문 표현 감지 후 일정 관련 대화인지 이진 분류 | RAGAS(질문 표현 판정) + classification metrics |
| 2 | 응답 긍정/부정 판단 | 애매한 응답 판정 후 긍정/부정 이진 분류 | RAGAS(애매한 응답 판정) + classification metrics |
| 3 | 날짜 판단 | 상대/반상대 날짜를 절대 날짜로 정규화 | exact match |
| 4 | RDB 저장 | 모달 확인 후 POST 요청 | success rate |

표 2. 인원 수 및 질문 유형별 실행 케이스

## 3. RAG 적용 지점

표 3. 규칙 기반 한계와 RAG 적용 방식
| 지점 | 규칙 기반의 한계 | 적용 방식 |
|---|---|---|
| 질문 표현 판정 | 어미 변형(할래?/허쉴?/ㅎㅅ? 등)이 계속 생겨 고정 목록으로 대응 불가 | 과거 판정 사례를 검색해 few-shot 근거로 LLM에 제공 |
| 애매한 응답 판정 | 긍정/부정 키워드 목록 밖의 응답은 판정 불가 | 과거 애매한 사례와 최종 판정 결과를 검색해 근거로 제공 |

사례집은 판정 결과가 누적될 때마다 자동으로 검색 대상에 추가되어, 별도 문서 갱신 없이 지속적으로 갱신됨.

## 4. 대화 상태 관리

대화 연속성은 State의 `pending_question` 필드로 관리함. 새 메시지가 일정 질문으로 판정되면 `pending_question`에 기록하고, 응답 판정이 완료되면 초기화함.

- 판단 방식: 매 메시지마다 messages 리스트 전체를 훑는 대신, `pending_question` 필드만 확인
- 미결정: `pending_question`의 유효 기간(TTL) 산정 기준 (추후 논의)

## 5. 평가 지표

표 4. 작업 품질 지표와 RAG 품질 지표
| 구분 | 지표 |
|---|---|
| 작업 품질 지표 | classification metrics(1차/3차), exact match(2차), success rate(4차) |
| RAG 품질 지표 | 문맥 정밀도, 문맥 재현율, 충실도, 답변 관련성(질문 표현/애매한 응답 판정) |

## 6. 남은 미결정 사항

- 날짜 판단 시, `messages` 리스트에서 질문 메시지를 어떻게 찾아 날짜를 추출할지
- `pending_question`의 유효 기간(TTL) 산정 기준
